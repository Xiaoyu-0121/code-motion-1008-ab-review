独立耗时判定（A/B）

判定依据：仅根据 metrics.jsonl、runs.jsonl、cases.json 重新推导。未把 judge_report.md 当作事实；未查看 plugin 源码。

计入均值/标注的完整成对：9 对（排除 c08——base 未交付 delivered=false）。
Δ = perf − base（分钟）。|Δ| ≤ 2 → 噪声。某项「声称改动」只有在对应信号朝正确方向变化，且该阶段能解释 Δ 中有意义的一部分时，才算归因成立。

1. 总评

九对完整成片的墙钟耗时均值差约 −2.0 分钟（base 38.0 → perf 36.0），落在噪声带；中位数（−5.2）被少数「计划/结构分叉」的大起大落拉偏，并不是某套机制稳定奏效。本轮四项声称的耗时改动没有可信因果效应：async 相关信号（main_poll_*、resume_gap）平均持平甚至变差；scoped onboarding 失败——即便 child_to_first_write 偶有下降，children_reading_engine 仍接近打满（常为 100%）；asset_cp / asset_retype_or_find 方向不稳定，且从不足以解释数分钟级 Δ；entry_fixes 两边本来就是 0。观察到的变快，以及 c02 的大幅变慢，更宜标为 agent 随机性 / 执行计划分叉（子 agent 数量翻转、setup 或 post_children 文字阶段膨胀、render/compress 形态变化），而不是补丁生效。
